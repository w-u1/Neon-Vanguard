# 简历怎么写 / 面试怎么讲

这份材料配合 `NeonVanguard` 工程使用。目标是把"我做了一个小游戏"讲成
"我能独立负责一个完整玩法模块"，这两者在面试官眼里差别很大。

## 一、简历条目（可直接用）

### 版本 A：突出完整度（推荐，适合投 Unity 客户端岗）

> **《Neon Vanguard》俯视角生存肉鸽 · 独立开发（Unity 2022.3 / C#）**
> - 独立完成从玩法设计到打包发布的完整流程，产出可运行 Windows 版本；
>   全场景、角色、特效、音效均由代码运行时生成，工程无预制体、无外部依赖。
> - 实现 **3 种手感差异化的武器**（连发手枪 / 扇形霰弹 / 穿透轨道炮）与 **4 类敌人 AI**
>   （追击摆动 / 重装冲撞 / 保持射程的远程 / 三技能循环的 Boss）。
> - 设计 **20 张可叠加的肉鸽强化卡**与 20 级经验曲线，抽象出唯一数值源 `PlayerStats`，
>   新增强化卡无需改动任何逻辑代码。
> - 自研**打击感系统**：屏幕震动、顿帧、命中闪白、伤害飘字、受击缩放，统一封装为可复用接口。
> - 性能优化：子弹/特效/飘字全部**对象池化**，运行期几乎无 GC 分配；
>   自研合成音效替代音频资源，构建包体不含任何音频文件。

### 版本 B：突出技术深度（适合投引擎/技术向岗位）

> - 采用 **SphereCast 连续碰撞检测**解决高速子弹穿透问题（轨道炮 78 单位/秒，
>   单帧位移超过敌人直径，普通触发器检测会漏判）。
> - 相机跟随、朝向插值统一使用 `1 - exp(-k·dt)` 实现**帧率无关平滑**，
>   避免 30fps / 144fps 手感不一致。
> - 通过 `[RuntimeInitializeOnLoadMethod]` + 代码构建舞台，消除预制体与 GUID 引用断裂风险，
>   使工程可干净地纳入版本控制（无二进制资源、diff 可读）。
> - 用**事件总线**解耦 UI 与玩法逻辑，UI 不持有任何敌人 / 波次导演的引用。

## 二、高频追问与回答要点

### Q1：为什么要"全部代码生成"，这不是自找麻烦吗？
**先承认取舍**，再讲收益，这是面试官最想听到的：
- 这是**作品集工程**，第一优先级是"任何人 clone 下来就能跑"，零导入步骤、零资源丢失。
- 没有预制体意味着**没有 GUID 引用断裂**、没有二进制资源，代码 review 与 diff 都干净。
- **但要明确说清代价**：正式商业项目不会这么做。美术接入、策划调参、热更新都依赖
  预制体 + Addressables，纯代码构建会让美术和策划无法参与。如果项目进入量产阶段，
  我会立刻改为"Prefab + ScriptableObject 配置 + Addressables"。
- 补充：我自己已经预留了退路 —— 美术资源走 `ModelLibrary` 统一加载，
  **取不到模型时自动回落到程序化几何体**，所以美术资源是可插拔的。

### Q2：子弹为什么会穿透？你怎么解决的？
- 根因：离散采样。`OnTriggerEnter` 依赖物理步进时的重叠检测，
  当单帧位移 > 目标直径（轨道炮 78 u/s，60fps 下单帧 1.3 单位，敌人直径约 1 单位）就会漏判。
- 方案：每帧记录上一帧位置，用 `Physics.SphereCastNonAlloc` 从上一帧位置向本帧位置**扫掠**。
- 用 `NonAlloc` 版本复用缓冲区避免每帧 GC。
- 关键细节：**不依赖工程里可能不存在的自定义 Layer**，而是先粗筛 LayerMask（拿不到就用 `~0`），
  再按组件（`GetComponentInParent<Enemy>()`）做精确敌我判定。这修掉了一个真实 bug：
  最初用 `LayerMask.GetMask("Enemy")`，工程没配这个 Layer 时返回 0，导致子弹永远打不中。
- 穿透时把射线起点推到命中点之外，避免同一目标被重复命中。

### Q3：对象池怎么设计的？为什么需要？
- 子弹在满配（分裂枪管 + 高射速）下每秒生成 50+ 个；每发 `new GameObject` 会带来
  GC 抖动，表现为周期性的掉帧。
- 实现：`Pool.Spawn(key, factory, ...)` / `Pool.Despawn(go)`，按 key 分桶，
  对象挂 `PooledObject` 标记记录所属桶；`ClearAll()` 在重开一局时统一回收。
- **踩过的坑**：最初 `ClearAll` 只销毁了池根节点，没处理"仍处于激活状态、正在飞行中"的对象，
  重开后场上会残留幽灵子弹。后来加了 `FindObjectsOfType<PooledObject>()` 兜底回收。

### Q4：打击感具体做了什么？
按"输入 → 命中 → 反馈"三层说：
1. **发射**：后坐力把玩家往后推（重武器更明显）、枪口火花、屏幕轻震、
   轨道炮额外加 45ms 顿帧。
2. **命中**：闪白 + 模型缩到 0.86 倍再弹回（"打中是有感觉的"）、
   按伤害大小自动调整字号与颜色的飘字、定向火花喷溅。
3. **击杀**：爆散粒子、屏幕震动、连杀计数（2.4 秒窗口内连杀累积分数倍率）。
- 强调：**同样的数值，有反馈和没反馈的体验差距是数量级的**，这部分投入产出比最高。

### Q5：难度曲线怎么调的？
- 敌人生命用**复合曲线** `1 + (wave-1)*0.17 + wave^1.35 * 0.012`，
  前期接近线性、后期加速，避免"一直线性"导致的后期无压力。
- 每波总数**封顶 62**、同屏上限**封顶 36** —— 这是性能与体验的双重约束，
  不封顶的话后期会变成幻灯片且玩家无法处理。
- 敌人类型按波次解锁（第 2 波暴君、第 3 波远程），**每几波给玩家一个新东西**。
- 每 5 波 Boss，且配少量杂兵，避免 Boss 战变成无压力的单挑。
- 每波结束回 6% 血 + 30% 概率掉回血包，给"苟住"一个正反馈但不过量。

### Q6：帧率无关的插值，你写的 `Lerp(a, b, 0.1f)` 有什么问题？
- `Lerp(a, b, t)` 固定 t 时，实际收敛速度**依赖调用频率**：高帧率收敛快、低帧率收敛慢，
  60fps 和 144fps 的手感不一样。
- 正确做法是 `a + (b-a) * (1 - exp(-k * dt))`，指数衰减与 dt 无关。
- 工程里相机跟随、敌人朝向、受击缩放全部用的是这个形式。

### Q7：中文字体怎么处理的？（体现工程细致度）
- 问题：TMP 的 `CreateFontAsset(string path)` 重载带 `#if UNITY_EDITOR`，
  而游戏脚本编译进**运行时程序集**，所以运行时**根本拿不到那个重载**
  （编译器把参数 1 解析成了 `Font` 类型，报 CS1503）。
- 解决：把中文字体作为 `.ttf` 放进 `Resources`，Unity 导入为 `Font` 资产，
  运行时用 `Font` 重载创建 TMP 动态字体资产，中文按需生成字形（不会把整个字库烘进图集）。
- 另外还踩了一个坑：TMP 的 shader 不在包缓存里，必须先导入 **TMP Essential Resources**，
  否则运行时报 `shader is null`。我在构建脚本里用 `TMP_PackageResourceImporter.ImportResources`
  自动完成这一步，保证 clone 后第一次构建就是对的。
- 做了**三级回退**：工程字体 → 系统字体 → Unity 内建字体；TMP 不可用时自动降级到 Legacy Text。

### Q8：如果让你继续做一个月，你做什么？
按优先级给（这题考的是判断力，不要罗列一堆功能）：
1. **先做手柄支持与可访问性**（当前只有键鼠），这是留存的实际门槛。
2. **把敌人避障换成流场寻路** —— 目前是简单转向 + 刚体推挤，敌人多了会重叠。
3. **武器/敌人配置迁移到 ScriptableObject**，让策划不碰代码也能调平衡。
4. 内容量：更多武器、遗物词条、多地图，以及一个正式的存档系统（当前只有最高分）。
5. 用 Unity Profiler 做一轮真机性能压测，确认 200 敌人同屏的帧率上限。

## 三、演示建议（面试时怎么展示）

1. **先给结果**：直接双击 exe 玩 60 秒，让面试官看到能跑、好玩。
2. **再讲一个"最硬的坑"**：优先讲 SphereCast 那个 —— 它有明确的现象（子弹穿透）、
   明确的根因（离散采样）、明确的修复（扫掠检测），
   还附带一个"依赖不存在的 Layer 导致判定失效"的真实 bug，信息密度高。
3. **打开代码讲结构**：`Bootstrap.cs`（装配）→ `WaveDirector.cs`（节奏）→
   `Enemy.cs`（AI 共享受击逻辑）→ `Juice.cs`（打击感）。让面试官看到你是**有组织地**写代码，
   而不是把所有东西塞进一个 2000 行的文件。
4. **主动讲取舍**：CC0 美术资源的选择、"全代码构建"的代价、
   程序化音效的可替代性。**主动暴露权衡比只讲优点更可信**。
